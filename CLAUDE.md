## Overview

This is a Dune Indexer for the Twyne protocol built using the Sim IDX framework. It indexes blockchain data related to collateral vaults, liquidations, vault metrics, and governance parameter changes, then serves this data through a TypeScript API.

## Development Commands

### Building and Testing
- `sim build` - Compile Solidity listeners and generate TypeScript API schema
- `sim test` - Run Foundry unit tests for listeners (located in `listeners/test/`)
- `sim listeners evaluate --chain-id 1 --start-block 23248031` - Dry-run listener against historical blocks
- `sim listeners evaluate --chain-id <id> --start-block <num> [--listeners=<name>]` - Test specific listener with custom parameters

### Adding New Contracts
- `sim abi add abis/<path/to/abi.json>` - Register new ABI and generate Solidity bindings

### API Development
Follow the [Sim IDX local development setup guide](https://docs.sim.dune.com/idx/apis#local-development-setup) to run the API locally.

## Architecture

### Data Flow
On-chain activity → Listener Handler → Listener Emits Event → Database → API → Client

### Listener System (`listeners/src/`)

The indexer uses on-chain Solidity contracts (listeners) that react to blockchain events and function calls:

- **`Main.sol`**: Central trigger registration contract. Defines which chains, contracts, and ABIs to listen to
- **`TwyneVaultListener.sol`**: Tracks collateral vault operations (deposits, withdrawals, borrows, repays, teleports, liquidations) and emits position snapshots
- **`TwyneFactoryListener.sol`**: Indexes vault creation events from the collateral vault factory
- **`EVaultLiquidateListener.sol`**: Monitors external liquidations on EVaults
- **`EVaultParamUpdateListener.sol`**: Tracks governance parameter changes across EVaults
- **`PerBlockListener.sol`**: Creates periodic snapshots of vault metrics (runs per block)
- **`ChainlinkAggregatorListener.sol`**: Indexes Chainlink oracle price updates

**Key Pattern**: Most listeners use "pre" and "post" function handlers to capture state before and after transactions. The `TwyneVaultListener` includes a `getPositionSnapshot()` helper that fetches comprehensive vault state, including USD-denominated values via oracle calls.

**State Tracking**: Position snapshots include a `state` field ("pre" or "post") and `txType` field (e.g., "deposit", "withdraw", "borrow", "repay", "teleport", "liquidate") to track transaction flow. The `logIndex` counter ensures ordering.

### Generated Code
- `listeners/lib/sim-idx-generated/`: Auto-generated Solidity bindings from ABIs (regenerated by `sim abi add`)
- `apis/src/db/schema/Listener.ts`: Auto-generated Drizzle ORM schema from listener events (regenerated by `sim build`)

### API Layer (`apis/src/`)

TypeScript API using Hono framework and Drizzle ORM, running on Cloudflare Workers:

- **`index.ts`**: All API endpoints with pagination, filtering, and validation
- Chain ID filtering supported across all endpoints via `chainIds` query parameter (defaults to chains 1 and 8453)

**Key Endpoint Patterns**:
- Latest snapshots use subqueries to find max timestamp per vault
- Position snapshot queries filter by `state = 'post'` to avoid double-counting
- External liquidations join three tables: `externalLiquidation`, `vaultCreated`, and `preExternalLiquidation`
- Protocol stats aggregate USD values from latest snapshots and EVault metrics (filtered by symbol prefix "ee")

### Trigger Types in Main.sol

- `chainContract()`: Listen to specific contract address
- `chainAbi()`: Listen to any contract matching an ABI signature
- `chainGlobal()`: Listen to every block on a chain

## Important Patterns

### Database Schema from Events

Events in listeners define database table schemas. The event name converts to `snake_case` for the table name.

**Event Structure Guidelines**:
- For events with >10 properties, use a struct and emit with unnamed parameter: `event MyEvent(MyEventData)` not `event MyEvent(MyEventData data)`
- Use `@custom:index` annotations for database indexes on high-cardinality queries

**Example from TwyneVaultListener**:
```solidity
/// @custom:index vault_deposit_by_vault BTREE (vaultAddress, blockTimestamp);
/// @custom:index vault_deposit_by_user BTREE (userAddress, blockTimestamp);
event VaultDeposit(VaultDepositData);
```

### Position Snapshot Double-Counting Prevention

Position snapshots are emitted both "pre" and "post" transaction. When querying latest state or aggregating data, always filter by `state = 'post'` to avoid counting the same vault twice.

### Oracle Integration

The `TwyneVaultListener._getQuote()` function fetches USD prices from Euler Router oracles. It includes try/catch to handle oracle failures gracefully (returns 0 on error).

### Address Validation (API)

All API endpoints accept addresses with or without `0x` prefix, validate hex format, and check for exactly 40 characters (20 bytes).
